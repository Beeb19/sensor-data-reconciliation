However, the timestamp of that row is still valid and must be used when determining the earliest or latest timestamps for the overall timeline boundaries. For every incoming Alpha reading, compare it to the most recently accepted valid Alpha reading. Calculate the absolute rate of change in °C per elapsed minute. If the rate strictly exceeds 1.5°C/min, the new reading is a glitch. You must discard its temperature (treat it as null) but retain its timestamp for your bounds. Crucially, the next incoming reading must be evaluated against the last valid reading, ignoring any discarded glitches. The first valid temperature reading in the log is always accepted. Beta's ISO 8601 timestamps will contain various timezone offsets (e.g., +02:00 or -05:00), and the script must parse and normalize all of them to UTC before beginning the alignment.

The output must contain exact 1-minute intervals. The timeline begins at the floor minute of the earliest timestamp across both logs (e.g., if the earliest is 14:30:25, start at 14:30:00) and ends at the floor minute of the latest timestamp. Assign each reading to a minute bucket by flooring its timestamp. For each minute interval, convert Beta's Fahrenheit to Celsius. Average all valid (non-null) temperatures and vibration readings within that bucket. If a bucket contains multiple readings but some are null, average only the non-null values.

If a minute bucket contains no valid temperature data for a sensor (either no rows logged, or all nulls), apply linear interpolation to fill the gap using the nearest valid surrounding minutes. Do not interpolate missing vibration data; leave it empty. Leave leading or trailing missing temperature values empty if they cannot be interpolated. Write the final data with the headers: timestamp_utc (ISO 8601 format, e.g., 2024-05-12T14:30:00Z), alpha_temp_c (rounded to 2 decimal places), beta_temp_c (rounded to 2 decimal places), and beta_vibration_hz (rounded to 2 decimal places).
